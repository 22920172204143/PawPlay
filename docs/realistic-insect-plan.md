## 2. 现状与主要差距

具体证据见 [参考分析](reference-analysis.md)。

| 层面 | 当前仓库 | 目标与影响 |
| --- | --- | --- |
| 造型 | `PreyDrawer.ladybug()` 绘制橙色圆身、青色透明翅膀和发光触角端点 | 参考是红色斑点双壳、黄色腹部、黄色卷曲触角，需要重做模型 |
| 资源 | `assets/` 只有 DragonBones 说明；预期的 PNG、骨骼 JSON 和 3D 模型均未跟踪 | 不能靠修复加载器获得缺失的模型，必须交付可编辑源文件和运行资源 |

| 尺寸 | `Toy(1)` 使用固定 `displaySize = 400f` | 按有效画面短边定比例；参考红壳长边中位数约占短边 12.5% |
| 运动 | 沿采样点索引前进，`speed * dt * 6`；速度值不是屏幕距离/秒 | 按弧长驱动轨迹，移动速度、转向与局部动画有独立参数 |

| 状态 | 移动与 Canvas 绘制耦合，部分骨骼动画在 `draw()` 中推进 | 模拟更新独立于绘制，暂停、回放和多实例保持一致 |

现有 Compose 页面、音效/触觉服务和其他玩具可继续使用。优先替换单虫的模型和渲染，不把视觉复现扩成整款应用重写。

## 3. 技术路线

推荐 **Blender 可编辑建模 → glTF 2.0/GLB → Android Filament 实时渲染**。保持现有 Kotlin + Compose 应用结构。

| 选择 | 用途与判断 |
| --- | --- |
| Blender + GLB + Filament | 主线。模型可编辑，局部零件可动画，真实几何、材质和光照可在 Android 运行 |
| 3D 模型离线渲染成序列帧 | 仅作为性能受限时的候选降级；会失去部分实时光照和任意姿态能力，不能直接代替 3D 主线验收 |
| 继续增加 Canvas 渐变和二维拼图 | 旧玩具可以保留；不作为这只虫子的主要资产方案 |
| Unity/Godot 整体迁移 | 当前不选；会扩大 Android 页面、生命周期和打包的改动范围 |

Filament 官方提供 Android 库、glTF 加载、PBR 材质和 bloom。选型依据见 [Filament 官方仓库](https://github.com/google/filament)。Blender 的 glTF 导出使用 [Khronos 官方导出器](https://github.com/KhronosGroup/glTF-Blender-IO)。资产约束遵循 [glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)。

实施时固定 Blender 版本；Filament 三个 Android 依赖与 `matc` 等资产工具必须使用同一版本。具体版本在 P1 最小导入验证后锁定，不使用动态版本。暂不为了本次视觉工作升级现有 AGP/Kotlin/Compose。

### 3.1 造型与材质

参考表现是风格化的小瓢虫。3D 模型以匹配固定俯视投影为第一约束，厚度和反光保持克制，不能因为使用 PBR 就把它做成写实甲虫或高反光塑料球。

建议零件：

1. `abdomen`：饱满但较扁的黄色腹部，弱斑块纹理、受控自发光。
2. `shell_left/right`：红至洋红色双翅壳、深红/紫色斑点；壳体具有厚度，各自绕靠近头部的铰链开合。
3. `head`：黄色小头和蓝绿色眼点；比例按视频投影校准。
4. `antenna_left/right`：有真实截面的细曲线，末端卷曲，轻微非同步摆动。

当前参考不足以确定腿、腹面和背面细节；这些部分只补齐必要几何，不让未观察到的结构改变目标轮廓。先以可编辑网格和确定的 UV/材质制作首只模型，不把单张生成图片当成可运行的 3D 资产。

保留 `.blend`、贴图与导出配置，运行时交付 `.glb`。程序化材质在需要时烘焙到 glTF 支持的通道；每轮检查导出后颜色与动画，避免只在 Blender 中正确。

初始预算仅用于控制工作量：单虫约 8k–20k 三角形、1k 贴图起步、少量材质。是否增加细节由手机实际画面决定，性能数据以真机测量为准。

### 3.2 相机、光照与背景

- 使用固定俯视正交相机作为起点；正交是复现选择，尚不能据视频断言原作相机类型。
- 模型统一采用 glTF `+Y` 向上、约定 `-Z` 为前方；一个适配层完成屏幕坐标和朝向转换，移除这条新路径上的经验角度补丁。
- 单虫红壳投影长边先按有效画面短边的 `0.125` 标定，再通过人工轮廓确认。头、触角、光晕另计，不与 `displaySize` 直接等同。
- 参考对比模式固定相同宽高比和视口；手机正常运行按短边缩放，背景和模型不拉伸。
- 弱主光和环境补光提供浅体积；黄色自发光与 bloom 分开控制，避免腹部过曝成白色。
- 参考中的暖色光晕由独立参数控制；材质自发光不等同于照亮地面，需要时使用单独的局部补光或地面光斑。
- 接触阴影应柔和、轻量，首先核对参考可见程度。避免追加重阴影改变原图气质。
- 首先复用现有 `bg_mulch.jpg` 调整尺度、曝光与暗角。它与视频是否为同一原图尚未确认，不用背景差异掩盖或放大虫子差异。

### 3.3 动作与移动

把局部动画与全局运动分开：

- 局部：双壳开合、触角摆动、轻微起伏。先手工拟合关键姿态和时间，再决定适合循环曲线还是程序参数。
- 全局：停顿、启动、移动、减速、转向、离屏/回归。移动采用弧长参数化，速度统一为“体长/秒”或归一化画面距离/秒。
- 模型每实例保存自己的动画相位，避免共享状态使后续多虫同时抖动。
- 停止平移时允许保留视频中实际可见的局部动作；不要把“没有位移”等同于“完全冻结”。
- 关闭新虫子当前 15%/10% 的整体拉伸压扁，先由局部部件表达动作。
- 星星从尾部附近发出，按距离/状态调节密度；寿命、大小、透明度和滞后量按参考片段校准。

提供两个开发验证模式：`ReferenceReplay` 重放固定参考轨迹和时间；`FreeRoam` 使用同一模型、动画与动作参数自主游走。固定回放用来消除随机路径对视觉比较的干扰，不能作为最终交互玩法的替代。

### 3.4 Android 接入边界

先增加开发验证入口，在其中运行单虫 Filament 场景。场景内统一绘制背景、虫子和拖尾；不让 Canvas 与 Filament 同时占用同一个 `Surface`。

建议职责拆分，名称可在实施时按现有结构调整：

| 组件 | 职责 |
| --- | --- |
| `ReferenceBugController` | 固定步长模拟、状态转换、参考回放和随机游走；产生不可变场景状态 |
| `BugVisualProfile` | 模型路径、尺寸、材质、动作及光效参数；记录配置版本 |
| `FilamentBugRenderer` | GLB 加载、相机、模型局部姿态、背景、灯光、粒子；消费场景状态 |
| `FilamentGameView` | Surface、帧调度、资源所有权和触摸坐标转换 |
| 游戏会话控制层 | 现有捕捉、换玩具、音效和触觉事件；不依赖具体绘制 API |

第一轮只打通新虫子。正式接入时，在玩具切换边界选择旧 Canvas 场景或新 3D 场景，并保证只有一个渲染循环持有当前显示区域。保留其他玩具的现有路径。

使用一个明确的线程拥有 Filament 对象和销毁操作；触摸等外部输入排队进入更新逻辑。暂停时停止模拟和帧调度，恢复时重置时钟；处理 Surface 重建、横竖屏、离开页面和音效停止。模型缺失在开发验证中应明确报错，不能悄悄回退后仍声称在显示新模型。

## 5. “几乎相同”如何验收

先固定参考时间、相机、虫子尺寸、有效视口、曝光与播放速度，再比较。原视频的黑边、水印、二维码和片尾不作为游戏效果目标。

| 项目 | 对比方式 | 初始目标，待标注后细化 |
| --- | --- | --- |
| 轮廓与结构 | 4 个朝向/开合姿态，原尺寸与放大图，使用人工确认的主体遮罩 | 主体遮罩 IoU 争取 ≥0.90；这是辅助指标，不表示“90% 相似” |
| 屏幕比例 | 红壳投影长边 / 视口短边 | 相对参考偏差约 ≤5%，头和触角另外比较 |
| 颜色与体积 | 排除背景后查看红壳、黄腹、斑点、眼点与高光 | 不明显偏橙/偏青；腹部细节未被发光吞掉，壳体不变成塑料球 |
| 局部动作 | 对齐关键帧后逐帧与循环播放 | 关键开合时刻初始容差约 2 个源视频帧；触角、身体动作不抢主体节奏 |
| 固定回放 | 叠加轨迹与关键转向/停顿时刻 | 目标位置误差小于约 1/4 体长；未可靠跟踪的区间人工核对 |
| 自主行为 | 停顿、启动、转弯、出入边界的连续片段 | 与参考节奏一致，无跳变、滑行错朝向和路径采样密度导致的忽快忽慢 |
| 光效与拖尾 | 在统一背景/曝光下比较整段视频 | 亮度、光晕范围、星星大小与消散速度接近 |
| 手机运行 | 指定实际手机、分辨率、刷新率和配置，连续运行 10 分钟 | 以 60 fps 为目标，记录平均值、P95 帧时间、卡顿和温升后变化；未实测前不承诺达标 |

静态模型通过不能代替 Android 渲染通过；电脑视频通过不能代替手机性能通过。算法指标只帮助定位差异，最终由用户判断本轮优化是否有效。
